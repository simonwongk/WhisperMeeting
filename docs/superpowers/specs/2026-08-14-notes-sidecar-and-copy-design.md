# Durable notes sidecar + copyable summaries — design

**Date:** 2026-08-14
**Status:** approved

**Goal:** Transcribed and summarized text must never again exist only inside `meetings.json`, and
summary content (summary, key points, action items) must be easy to copy — whole, per section, or by
mouse selection.

**Context:** On 2026-08-14 the meeting index was wiped and every transcript went with it, because
transcripts and summaries live only in `meetings.json`. The recording folders survived. F187 makes the
index hard to lose; this feature makes the *text* survivable even if the index is lost anyway.

---

## Feature 1: `notes.md` sidecar in each recording folder

### What is written

`Recordings/<meeting-uuid>/notes.md`, generated by the existing
`MeetingNotesExporter.markdown(title:dateText:durationSeconds:languageCode:summary:transcriptText:notes:markers:segments:)`
(`Sources/WhisperCore/MeetingNotesExporter.swift:7`) — the same function behind the manual "Export…"
button, so the sidecar and manual export can never drift. It contains title, date, duration,
language, notes, summary, key points, action items, and the full transcript.

### When it is written

1. **On change, debounced.** Every transcript/summary/notes mutation funnels through
   `MeetingStore.upsert`, `update(id:)`, `editTranscript`, and `editNotes`. A single hook in those
   methods schedules a per-meeting debounced sidecar write (the F40 pattern that already coalesces
   per-keystroke index writes; reuse the same delay parameter so tests can drive it explicitly).
2. **Startup backfill, idempotent.** Once per launch, for every meeting whose recording folder exists:
   compose the markdown and write it only if the file is missing or its content differs. This
   immediately covers everything already transcribed today.

Both paths **compare before writing** (compose, read existing, write only on difference). The
markdown excludes tags/pinned, so a pin toggle routed through `update(id:)` composes identical
content and must not rewrite the file.

### Safety rules (non-negotiable)

- **No sidecar write while degraded.** The backfill and the debounced writer both check
  `isDegraded` first. F187's promise — nothing in the library is written while read-only — stays
  absolute. (The mutation hooks are already unreachable while degraded, since the mutators refuse;
  the explicit check covers the backfill and any future caller.)
- **Sidecar writes never touch audio and never create folders.** Write only into a recording folder
  that already exists; if the folder is missing (e.g. an audio-less record), skip silently. Never
  `createDirectory`.
- **Failures are silent by design, and documented as such.** The sidecar is *derived* data,
  regenerable from the index at any time; a failed write loses nothing. This is the deliberate
  inverse of the F187 silent-failure fixes, where the failing store was the source of truth. A code
  comment must state this distinction so a future reader doesn't "fix" it into an alert.
- The sidecar is **not** read by the app, ever. It is write-only insurance. Recovery from sidecars is
  a human act (open the folder, read the markdown).

### Interaction with existing behavior

- Deleting a meeting deletes its folder, sidecar included (accepted in design questioning).
- The backup feature already snapshots `Recordings/`, so dated backups include sidecars with no
  change to `BackupCoordinator`.
- `docs/RECOVERY.md` gains a line: each recording folder holds a human-readable `notes.md` with the
  transcript and summary, alongside the audio.

## Feature 2: Selectable text + per-section copy

- `.textSelection(.enabled)` on the summary paragraph, key points, notes, and transcript text views
  in the meeting detail (`ContentView.swift` `summaryBody` at `:2448` and the transcript view), same
  as `DictationView.swift:59,168` already does.
- Per-section copy buttons beside the existing whole-summary "Copy"/"Export…":
  - **Copy Key Points** — the `• point` lines only.
  - **Copy Action Items** — via `MeetingNotesExporter.actionItemLine`, the same formatting the
    whole-summary copy already uses (`ContentView.swift:2495`), so owner/due/done render identically
    everywhere.
- Reuse the existing `copy()` helper and `TransientAcknowledgment` checkmark pattern
  (`ContentView.swift:2182`). No new visual vocabulary.
- Action-item *cards* stay interactive (toggle done, owner, due); selection is enabled on their text,
  not on the controls.

## Out of scope

- Reading sidecars back / restoring from them in-app (F193 owns in-app recovery).
- Exporting to configurable formats or locations (the manual "Export…" button already exists).
- A separate mirror folder outside the library (declined in design questioning).

## Testing

- Store-level: a transcript edit produces/updates `notes.md` after the debounce flush; content
  matches `MeetingNotesExporter.markdown` output exactly.
- Backfill: a library with transcripts but no sidecars gains them on load; a second load rewrites
  nothing (assert file mtime or write-count unchanged).
- Degraded: **no sidecar is written while the library is read-only** — backfill over a degraded
  store leaves recording folders untouched. Must be red without the guard.
- Audio-less record: no folder is created, no write is attempted.
- SwiftUI selection/copy buttons: no view-render harness exists — manual verification, recorded as
  "Not planned:" per AGENTS.md.
